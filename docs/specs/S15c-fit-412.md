# S15 slice c · fit the UI to the 412 panel + enlarge primary tap targets

## Purpose

Device bring-up (S15b) put the real `ff_shell` UI on the Waveshare 1.46 glass —
but the whole design renders at `FF_THEME_PUCK_PX = 440` inside a
`FF_THEME_WINDOW_PX = 456` window, while the panel is **412×412**. The UI
overflows the glass by ~28 px, so the display scrolls to reveal the off-screen
top (battery/time) and bottom (map indicator) — that's the entire "scrollbars /
moving dots" symptom seen on hardware. This slice fits the design to the real
panel so it fills the glass with no overflow and no scroll.

This ALIGNS the theme with what CLAUDE.md already calls authoritative — "the
mockup geometry (412×412 circle)". The 440/456 constants were the drift.

**Second, tied requirement (maintainer field feedback, on real hardware):** some
controls were hard to hit *even sober* — Settings controls and especially the
Settings **back button**. So the fit is not "shrink everything 6.4%": primary
controls must come out **more** tappable, not less. Firefly's whole review bar
is the tired-raver-at-2am; a back button you can't reliably press fails it.

## What breaks on a naive rescale (measured)

Setting the theme to 412 is NOT a pure constant change:
- `scr_settings.c:119` `_Static_assert` fails ("last row must stay inside the
  puck's own square") — the settings layout has fixed-pixel row math that
  overflows the smaller puck.
- The S06 **device fonts are fixed sizes** and do not scale with the puck, so a
  6.4%-smaller container can clip text that fit at 440.
So the fit is a real relayout pass, face by face — not just editing two `#define`s.

## Approach

- **Theme → 412.** `FF_THEME_PUCK_PX = 412` (the puck fills the panel);
  `FF_THEME_PUCK_RADIUS_PX` follows (206). `FF_THEME_WINDOW_PX`: the puck is the
  device panel, so 412 is the real size — the sim window may keep a small margin
  for a backdrop, but the puck it renders must be 412 so sim and glass match
  pixel-for-pixel. State the choice in the PR.
- **Lean on theme-relativity.** Every screen already lays out relative to
  `FF_THEME_PUCK_PX`/`RADIUS` (verified: all screen files reference them), so
  most geometry rescales automatically. The work is the fixed bits: the
  `scr_settings` row math, and any face whose text/controls no longer fit.
- **Fonts.** Where text overflows its now-smaller container, drop to the next
  S06 device font size or reflow the layout — never clip. Check EVERY face
  renders its full content within the 412 circle.
- **Fix the assert honestly.** `scr_settings.c`'s `_Static_assert` must pass
  because the layout genuinely fits, not by weakening/removing the assert.

## Tap targets (the field-feedback half — do not treat as optional)

- Keep the global floor `FF_THEME_MIN_HIT_PX` (44) and `FF_HIT_MIN_GAP_PX` — the
  `test_face_hit_targets.c` global sweep must stay green at 412.
- But PRIMARY controls go GENEROUSLY above the floor: Settings rows/toggles and
  **the Settings back button** especially. The back button should be a large,
  obvious, comfortably-hittable target — size it for big hands / gloves / 2am,
  not to the 44px minimum. If a control can be bigger without colliding
  (the sweep proves it), make it bigger.
- Re-run the global adjacency sweep after resizing; the enlarged controls must
  pass with margin, not scrape the floor.

## Verification

- Sim gate green (`ctest`), tap-target sweep green, `test_scr_intent`/nav green.
- **All goldens regenerated at 412** (every `radar_*`, `now_*`, `signals_*`,
  `compose_*`, `settings_*`, `flare_*`, `map_*` — the whole set moves). This is
  a deliberate, wholesale golden refresh: note it explicitly, and confirm the
  ONLY intended change is the 412 rescale + the enlarged controls, not a
  regression riding along.
- **Hardware is the real gate** (maintainer + board 2): the UI fills the glass,
  battery/time and map indicator visible WITHOUT scrolling, no scrollbars, no
  free-scroll; and the enlarged Settings controls + back button are comfortably
  hittable. A photo per face in the PR.

## Acceptance criteria

1. Theme is 412 (puck fills the panel); on device the whole UI is visible with
   NO scroll — battery/time (top) and map indicator (bottom) on-screen at rest.
2. Every face renders fully inside the 412 circle: no clipped text, no cut-off
   or off-glass controls. `scr_settings`'s row assert passes because it fits.
3. Settings controls and the Settings back button are enlarged and comfortably
   tappable — visibly bigger than the 44px floor; the back button is an obvious
   large target.
4. All goldens regenerated at 412; `test_face_hit_targets` global sweep green;
   full sim gate green.
5. Hardware-verified on board 2 (photos): fills the glass, no overflow/scroll,
   primary controls easy to hit.

## Out of scope (tracked, not dropped)

Per-control calibration of touch coordinates (accuracy), power/idle, UART/comms
— all later slices. This slice is geometry + primary-control sizing only.
