# S28 — On-glass navigation gestures (edge-swipe BACK / HOME, long-press flare)

## Why
The printed case's physical home/BOOT cap is unreliable (Jake, on-glass 2026-09-04). Touch is reliable. Give BACK and HOME a touch path that cannot collide with scrolling. History to respect: PR #130 fixed "scrolls accepted as swipes" (a vertical top-swipe to Map ate list scrolls); S26 slice e then retired the swipe carousel entirely — `scr_nav.c` no longer emits `FF_INTENT_SWIPE` and the tileview's gesture machinery must stay untouched (tiles `LV_DIR_NONE`, no `LV_DIR_HOR`, no re-enabling LVGL GESTURE routing). S28 adds gestures that are gated on WHERE the touch starts (rim zones) and on axis lock, recognised mid-drag from raw indev points, not from LVGL's GESTURE events.

## Gestures (display-space pixels, 412×412, glass circle centre (FF_THEME_GLASS_CX, FF_THEME_GLASS_CY) = (208,206), radius FF_THEME_GLASS_R = 200; use the theme constants, flip-aware helpers `ff_theme_glass_cx/cy(flip)` if they apply to touch space — check how touch coordinates are flipped and use the same space the screens hit-test in)
- G1 BACK — touch DOWN inside the glass circle AND within the LEFT rim zone (x ≤ cx − r + 28), then the finger travels dx ≥ +56 px within 500 ms of DOWN, with |dy| ≤ 0.6·dx at the moment dx reaches 56, and with axis lock: if |dy| exceeds 24 px before dx reaches 56, the gesture aborts for this touch (it is a scroll). Recognised mid-drag; emits BACK once; nothing else for the rest of that touch.
- G2 HOME — touch DOWN inside the circle AND within the BOTTOM rim zone (y ≥ cy + r − 28), then dy ≤ −64 px within 500 ms with |dx| ≤ 0.6·|dy| and axis lock (|dx| > 24 before |dy| reaches 64 aborts) and mean speed ≥ 0.25 px/ms. Emits HOME once.
- G3 LONG-PRESS FLARE — on the RADAR face only: DOWN anywhere inside the circle on a NON-interactive object, held ≥ 1200 ms with total movement ≤ 12 px → emits QUICK_FLARE (same countdown/cancel takeover as the 5-tap `FF_INTENT_QUICK_FLARE` path; same sounds). Recognised from a tick, not release. Interactive = objects created through `ff_scr_button_create` (scr_nav.c) — tag them with `LV_OBJ_FLAG_USER_1` there (one place) and refuse G3 when the press target or any ancestor up to the face root carries USER_1. If a legacy long-press→OPEN_SETTINGS hook still exists on any face, remove it (Settings lives in the launcher now).
- A touch that starts outside the rim zones can never become G1/G2. A touch that starts in a rim zone but moves the other axis first is a scroll and is left alone. Gestures are ignored entirely while a takeover is active (FLARE, POWER_MENU) and while the wake-only touch gate is swallowing the first touch after wake (feed the FSM only from touches the shell would deliver as input).

## Semantics of BACK (extends the existing `FF_INTENT_BACK`, mark PR2 title `[api]`)
Handled in the shell in this order: (1) modal COMPOSE up → pop it (existing); (2) INBOX with a thread open → same effect as `FF_INTENT_INBOX_CLEAR_TARGET` (back to the list); (3) SETTINGS on a sub-page → back to the settings root page; (4) any other base face → same as `FF_INTENT_HOME` (launcher); (5) LAUNCHER → no-op. HOME is the existing `FF_INTENT_HOME`. Recognised BACK/HOME play the UI tick sound (respect `ui_ticks`).

## Core module (PR1, Tier 3): `firmware/core/include/ff_gesture.h` + `firmware/core/src/ff_gesture.c`, pure C11, no I/O, no LVGL.
```c
typedef enum { FF_GESTURE_NONE = 0, FF_GESTURE_BACK, FF_GESTURE_HOME, FF_GESTURE_LONG_PRESS } ff_gesture_kind_t;
typedef struct { int16_t cx, cy, r; int16_t rim_px; int16_t back_travel_px, home_travel_px; int16_t axis_lock_px; uint16_t window_ms; uint16_t long_ms; int16_t long_slop_px; bool long_press_enabled; } ff_gesture_cfg_t;
void ff_gesture_cfg_default(ff_gesture_cfg_t *cfg, int16_t cx, int16_t cy, int16_t r);  /* 28, 56, 64, 24, 500, 1200, 12 */
typedef struct { ff_gesture_cfg_t cfg; /* FSM state: phase, x0,y0,t0, last x,y, done flag, zone */ ... } ff_gesture_t;
void ff_gesture_init(ff_gesture_t *g, const ff_gesture_cfg_t *cfg);
void ff_gesture_set_long_press(ff_gesture_t *g, bool enabled);      /* glue flips this per active face */
ff_gesture_kind_t ff_gesture_feed(ff_gesture_t *g, bool down, int16_t x, int16_t y, uint32_t now_ms); /* every DOWN/MOVE/UP sample */
ff_gesture_kind_t ff_gesture_tick(ff_gesture_t *g, uint32_t now_ms);  /* long-press timing; returns LONG_PRESS at most once per touch */
```
Wrap-safe time via `ff_time_reached` (ff_clock.h). At most one recognition per touch; after recognition the FSM is DONE until UP. Unit tests (Unity, ctest, names `S28_AC<n>_...`): AC1 left-rim swipe → BACK exactly once; AC2 same motion starting 40 px inboard → NONE; AC3 vertical scroll starting at the left rim → NONE; AC4 slow swipe (600 ms) → NONE; AC5 bottom-rim swipe up → HOME; AC6 diagonal beyond the ratio → NONE; AC7 long press 1200 ms with slop ≤ 12 → LONG_PRESS from tick, with 20 px movement → NONE, disabled flag → NONE; AC8 no second event after recognition until UP; AC9 DOWN outside the glass circle (a corner pixel) never starts a gesture; AC10 time wrap around 0xFFFFFFFF still recognises. Add the sources to the core sources.cmake and pass the sources-complete guard.
